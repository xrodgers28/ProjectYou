Architecture Map

v1.0

How the Project YOU Operating System is wired end to end — from where thoughts get captured, through the database and the scheduled jobs, to how every page is published and rendered. Read it top to bottom: inputs flow down into data, automation acts on the data, and the delivery pipeline turns it into the pages you use.

Overview Data Flow Diagram Knowledge Graph Interactive Knowledge Graph Architecture Map
1 · Capture & InputsGetting things in
Drafts appDictated notes (Apple Watch / phone) — the Task Capture pipeline reads the inbox and files each note.
Voice & text on-pageWeb Speech mics on Mission Control, Daily Habits, the board — write straight to the inbox.
StravaCardio activity synced into the Quantified Self log.
TripIt (planned)Travel history feeding the Where-I've-Been tracker.
▼
2 · DataSupabase — Postgres
Single source of truth. Row-level security by email; Realtime on the live boards. Every table below is owned by Scott.
todosToday's Tasks board — tasks, habits, est/act/log, rollover.
session_todosThe All ToDos running record (our chat work).
inboxCaptured notes awaiting routing.
qs_logQuantified Self master log; habits auto-log on tick.
daily_templateThe standing daily set behind the Daily Habits editor.
compass_questionsYear Compass prompts + hints.
content poolsAI deck tips / insights / platforms, Clever Phrases.
pagesEvery page's HTML (gzip+base64) — the deploy source.
app_metaApp-level settings and flags.
▼
3 · Automation & SchedulesJobs that act on the data
Publish workflowGitHub Action reads the pages table every ~5 min, unzips each row, writes & commits to the repo. Skips corrupt rows.
AI Deck generatorComposes a fresh daily deck from the content pools (5am).
Nightly reconciliationAudits the Docs Library & nav, appends findings (2:30am).
Task-capture sweepTurns Drafts notes into to-dos on a recurring schedule.
▼
4 · DeliveryFrom database to a rendered page
pages table → GitHubThe publish workflow mirrors HTML into the repo (xrodgers28/ProjectYou).
GitHub PagesServes and renders the HTML (Supabase's own domain returns plain text, so Pages is the render host).
Master navnav-config.js + navpatch.js — one config stamps the shared nav (and any sub-nav) onto every page.
▼
