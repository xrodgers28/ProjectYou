Nightly Reconciliation — what gets checked while you sleep

The Docs Library is reconciled automatically every night. This page is the manifest: it lists exactly what is reconciled, what "reconcile" means, and when it last ran.

Runs: every night at 2:30am ET, unattended (a scheduled task). It also runs on demand as part of [wrap] and /morning, which work from the same list.

Last run: pending first nightly run · Status: awaiting first run

What "reconcile" means

For each cluster below, the nightly pass will: check the files agree with each other, flag contradictions, stale numbers, and near-duplicates, propose which document is canonical, and never silently merge, delete, or edit a note Scott authored himself. Anything it finds is written back here as a dated findings list for review — it proposes, it does not overwrite.

Reconciled nightly — the Docs Library (this area)

Every document shelved in the Library is checked for internal drift against its neighbours. Grouped as they appear on the shelf:

  • Start Here — SER Operating System spec, Feature Set, CoWork Project Brief, CoWork Project Instructions. These restate the system to each other, so they drift first.
  • Features — Drafts Import, AI Intelligence. Checked against the live services they describe (endpoints, table names, section strings).
  • Build & Deploy — Web-App Build Playbook, Build Directory, ProjectYou Deploy & Hosting, the two nav handoffs, the deploy notes, the AI-Favorites build. Watch for hosting story drift (Supabase is the final host; GitHub Pages retired) and nav blocks that no longer match the live pages.
  • How We Work — how-we-work-rules, its-a-wrap, status-check, morning, log-accomplishments, new-project. Each skill backup is checked against the installed account skill for re-save drift, and against /preferences.md.
  • Templates & Assets — Start-a-New-Project, the brief/instructions templates, the Session Tracker template. Checked that they still match how live projects are actually structured.
  • Governance — Interface-Directions (capture + routing log) and the Reconciliation Watch List itself.

Reconciled nightly — the drift clusters (from the Watch List)

The Library pass rolls in the existing Reconciliation Watch List tiers:

  • Tier 1 (high drift): each active project's Brief vs Instructions vs Description/Knowledge Base; any multi-session spec set.
  • Tier 2 (weekly): TreadWell brief/spec/roadmap overlap; Project YOU description/brief/KB; the global trio (Feature Set vs the .docx spec vs Interface-Directions).
  • Systemic: how-we-work-rules vs /preferences.md; skill backups vs installed skills.

Also checked

  • Live nav vs handoffs — the Operating System nav group on the live Supabase pages against the nav-handoff docs, so the documented nav and the deployed nav stay in step.
  • Broken Library links — every hard link on the Library resolves to a live doc.

What it does NOT do

It does not edit, merge, or delete Scott's own notes; it does not touch project deliverables (research, databases, decks) — only the OS/system documentation shelved in the Library and the watch-list clusters; it does not publish changes on its own beyond updating this report's findings and timestamp.
